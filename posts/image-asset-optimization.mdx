### Content Delivery Network (CDN)

A CDN is a distributed network of servers that serve static content for a website. Using CDN will help us in two ways:

<ol>
    <li>
        <strong>Less bundle size:</strong> the image is seperately uploaded to cdn server and removed from the codebase, resulting in less bundle size.
    </li>
    <li>
        <strong>Low latency:</strong> CDN provides edge servers across the globe and caches these files, which helps in delivering static assets to user based on nearest server - which is efficient.
    </li>
</ol>

We'll be using <a target="_blank" href="https://cloudinary.com/">Cloudinary</a> as our CDN provider. Register/login on the platform and simply click on the "Upload" button on the top-right corner. And copy the cloudinary link for the uploaded image. Delete the image from our codebase and replace it with cloudinary link. And that's it the hero image is on CDN now and it improved

<img

/>

The results are massive we took down the load time for image from 8.88s to 45.79ms. There you go, that is optimization all about.

### Use modern image formats

AVIF and WebP are image formats that have superior compression and quality characteristics compared to their older JPEG and PNG counterparts. Encoding your images in these newer formats is a good strategy to reduce the download size of images. Both the formats are supported in new versions of all major browsers. - <a target="_blank" href="https://developer.chrome.com/docs/performance/insights/image-delivery#use_modern_image_formats"><i>Chrome for Developer Docs</i></a>

There both online and Command Line (CLI) tools available to convert images to WebP and AVIF but we don't need them because our CDN provider - Cloudinary, on-the-fly process the images and convert into both WebP and AVIF. 

Simply changing the link from <code>https://res.cloudinary.com/demo/image/upload/hero-background.jpg</code> to <code>https://res.cloudinary.com/demo/image/upload/hero-background.avif</code> will serve the WebP/AVIF format image.

#### Automatic quality selection by Cloudinary

Cloudinary's intelligent quality and encoding algorithm analyzes an image to find the best quality compression level and optimal encoding settings based on the image content and the viewing browser, in order to produce an image with good visual quality while minimizing the file size.

We can simply add a query paramater <code>q_auto</code> to our cloudinary image link and cloudinary will do it's magic. So, our link will look like:  

<code>https://res.cloudinary.com/demo/image/upload/q_auto/hero-background.avif</code> 

Addtionally, cloudinary provides setting to further fine the automatic quality selection:

- <code>q_auto:best</code>: Less aggressive algorithm. Generates bigger files with potentially better visual quality. Example of a target audience: photography sites that display images with a high visual quality.

- <code>q_auto:good</code>: nsuring a relatively small file size with good visual quality.

- <code>q_auto:eco</code>: More aggressive algorithm, which results in smaller files of slightly lower visual quality. Example of a target audience: popular sites and social networks with a huge amount of traffic.

- <code>q_auto:low</code>: Most aggressive algorithm, which results in the smallest files of low visual quality. Example of a target audience: sites using thumbnail images that link to higher quality images.

Source: <a target="_blank" href="https://cloudinary.com/documentation/image_optimization#automatic_quality_selection_q_auto">Cloudinary Official Documentation</a>

### Responsive Images

Devices such as Laptop or TV requires a image with high resolution, so that it is not pixelated when rendered. Similarly, a smaller screen size device - might not be required to render a high resolution image that is not required. We'll need to optimize the images for different size devices. 

#### The `<picture>` element

The `<picture>` HTML element contains zero or more `<source>` elements and one `<img>` element to offer alternative versions of an image for different display/device scenarios. - <a target="_blank" href="https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/picture"><i>MDN Docs</i></a>

We'll replace our existing `<img>` with the `<picture>`:

```html
<picture>
	<source 
		srcSet="https://res.cloudinary.com/demo/image/upload/q_auto:low/hero-background.avif" 
		type="image/avif" 
		media="(max-width: 640px)"
	/>

	<source 
		srcSet="https://res.cloudinary.com/demo/image/upload/q_auto:good/hero-background.avif" 
		type="image/avif" 
		media="(max-width: 1920px)"
	/>

	<source 
		srcSet="https://res.cloudinary.com/demo/image/upload/q_auto:best/hero-background.avif" 
		type="image/avif" 
		media="(min-width: 1921px)"
	/>

	<img 
		src="https://res.cloudinary.com/demo/image/upload/q_auto:good/hero-background.avif"
		alt="Hero Background Image"
	/>
</picture>
```
<ol>
	<li>`<source>` element offers same same media in multiple file formats based on the `media` attribute.</li>

	<li>`<img>` element describes the size and other attributes of the image and its presentation and act as a fallback in case none of the offered `<source>` elements are able to provide a usable image.</li>
</ol>

<img

Though, we rendered the image using best compression algorithm by adding `q_auto:low` parameter for small screen devices but the actual dimensions of the image downloaded is still as the original image `2000x1125` which is not required. To fix this, we'll simply add another parameter `w_<size>` in the url:

<code>https://res.cloudinary.com/demo/image/upload/q_auto:good,<strong style={{color:"red"}}>w_640</strong>/hero-background.avif</code>

Update all `<source>` elements `srcSet` attribute value with respective width parameter.

> We can optimize subsequently loads of the same image using `Cache-Control` header but as we our using Cloudinary - caching is managed by the CDN itself.

### Set the Priority: `fetchPriority`

The `fetchPriority` attribute allows a developer to signal that fetching a particular image early in the loading process has more or less impact on user experience than a browser can reasonably infer when assigning an internal priority. 

In the `<img>` tag of our `<picture>` element add the attribute `fetchPriority="high"`, signalling this image is important to load. 

Additionally, for images such as hero image, developers can use <a target="_blank" href="https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/rel/preload"><i>preloading</i></a> to complement the `fetchPriority` attribute and significantly contriuting to the webiste's <a target="_blank" href="https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/rel/preload"><i>Largest Contentful Paint</i></a> (LCP).

```html
<link 
	rel="preload" 
	as="image" 
	type="image/avif" 
	href="https://res.cloudinary.com/demo/image/upload/q_auto:good/hero-background.avif" 
/>
```

Ensure, to add the `loading=lazy` attribute to `<img>` which does not require load until a user scrolls to the section. Read more about Lazy Loading <a target="_blank" href="https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/Lazy_loading#images_and_iframes"><i>here</i></a>.
